Investment Committee · Decision Brief

Runes & Remnants

Keep investing hobby time, or declare the module done and stop — second review, following up a 2026-08-31 GO-IF.

GO-IF

Continue — but ship compatibility verification (v13, with smoke-tested sheets/hooks) and submit to the Foundry package directory, both by Nov 15, 2026, before any further feature work.

The trade-off

~105 hours are already sunk, and the one lever that tests the stated "real adoption" criterion — directory listing — has never been pulled; everything shipped this month improved depth for an audience of one. The strongest case against gating further work is the Bear's: one productive burst plus one busy night, bracketed by a 17-day gap, doesn't prove the 205-day and 66-day dormancy pattern has broken, so spending more hours now could be wasted on a project about to go quiet again. It doesn't carry the day because the gated task is small (14–30 hrs) and is itself a hedge against that exact risk: shipped before the next dormancy, the module survives being paused in a working, listed state; shipped after, it is frozen v12-only and undiscoverable indefinitely. The cheap test is worth running regardless of whether the burst cadence holds.

What the committee found

Bull

  • Dogfooding has started — real bugs (brew-stacking collision) found by playing, not reading code. This is the exact gate the prior GO-IF set, now firing.
  • Moat: a generated recipe journal with drift-proofing tests, plus 600+90 passing tests, means a copycat starts from zero on both content and safety net.
  • Load-bearing condition named by Bull itself: adoption stays theoretical until directory submission and v13/v14 verification actually happen.

Bear

  • "18 commits since last review" is one 4-day burst and one 8-commit night, not new sustained cadence — same binge-and-vanish shape as the 205d/66d gaps, repeating faster.
  • Two of those commits are ship-break-catch-after-the-fact incidents (pack corruption, brew-stacking bug), both in the 28% of source the test suite cannot reach.
  • compatibility.verified still reads "12" while that same untested boundary layer is exactly what a Foundry major-version bump would break first.

Allocator

  • ~105 hrs invested all-time, ~27 last month — effectively none of it spent on the ~10–20 hr task that would let a stranger find the module.
  • Cost to the real milestone (listed + verified + table actively using it): 14–54 hrs, base ~30 (8–12 weeks at current cadence).
  • On a blended view of all three success criteria the current path beats the alternatives — provided the cheap, long-avoided adoption step is actually taken.
